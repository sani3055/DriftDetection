ABSTRACT The exponential growth of intrusions on networked systems inspires new research directions
on developing artificial intelligence (AI) techniques for intrusion detection systems (IDS). In particular, the
need to understand and explain these AI models to security analysts (managing these IDS to safeguard their
networks) motivates the usage of explainable AI (XAI) methods in real-world IDS. In this work, we propose
an end-to-end framework to evaluate black-box XAI methods for network IDS. We evaluate both global
and local scopes for these black-box XAI methods for network intrusion detection. We analyze six different
evaluation metrics for two popular black-box XAI techniques, namely SHAP and LIME. These metrics are
descriptive accuracy, sparsity, stability, efficiency, robustness, and completeness. They cover main metrics
from network security and AI domains. We evaluate our XAI evaluation framework using three popular
network intrusion datasets and seven AI methods with different characteristics. We release our codes for
the network security community to access it as a baseline XAI framework for network IDS. Our framework
shows the limitations and strengths of current black-box XAI methods when applied to network IDS.

I. INTRODUCTION
The power of artificial intelligence (AI) has inspired
the development of fully automated intrusion detection
systems (IDS) [1], [2]. There are several AI techniques
that have been leveraged for such automation of intrusion
detection, including neural networks [3], [4], support vector
machine [5], [6], decision trees [7], [8], naive bayes [9],
[10], and random forest [11], [12]. However, most of these
AI methods (except decision trees for simple IDS) are
black-box models where no explanations about the AI’s
decisions are provided to the security analyst managing these
IDS [13], [14]. In particular, these previous AI-based studies
focused more on the classification accuracy of various AI
algorithms without providing insights about their behavior
and reasoning. Such a limitation motivates the pressing need
to leverage the relatively recent explainable AI (XAI) field for
enhancing the understandability of AI decisions in IDS [15].
There are several recent works that started exploring
leveraging XAI for IDS (e.g., [16]–[20]). The work [19]
proposed an abstract design for a human-in-the-loop
approach for intelligent IDS. Moreover, the work [16]
used only a simple decision tree algorithm for extracting
decision rules using exclusively the NSL-KDD benchmark
dataset [21]. The work [17] incorporated the local
interpretable model-agnostic explanations (LIME) [22]
to only provide local explanations for a single AI model
(SVM) for the used IDS. The work [18] infused the CIA
principle (‘‘C’’ stands for confidentiality of information, ‘‘I’’
stands for integrity of data, and ‘‘A ’’ stands for availability)
for enhancing the explainability of the AI model on the
CICIDS-2017 benchmark intrusion dataset. However, all of
these works did not provide a thorough evaluation of XAI
methods under different intrusion datasets and diverse sets
of AI models which affects the generality of such works.
Although XAI-based tools are going to be ubiquitous in
network security to aid security analysts to be more efficient

This paper aims to fill such a gap in evaluating XAI
methods for network intrusion detection systems. We build
a framework for evaluating XAI methods when applied to
network intrusion detection. We build on the prior work [23]
that delineates six metrics to evaluate XAI methods while
adapting these metrics for network IDS. These metrics are
descriptive accuracy, sparsity, stability, efficiency, robustness,
and completeness. These metrics are defined as follows.
• Descriptive Accuracy: The descriptive accuracy can be
interpreted as the importance of top intrusion features
when removed from the AI model. For instance, if an
intrusion feature is important, it is expected that the
intrusion prediction (by the AI model) will be less
accurate if such a feature is taken out. If the accuracy
drop after the feature is taken out is high, then the XAI
explainability power of such a feature is high.
• Sparsity: The sparsity measures the correlation between
the importance scores, given by the XAI method, of
different features. This is measured by comparing how
many features are below a certain small threshold. For
example, if 18 out of 20 intrusion features are below a
small threshold (close to zero), this means that there are
2 features with extremely high influence on the model’s
decision, and therefore the sparsity is high. Having
an XAI method with high sparsity can help security
analysts monitor their network traffic by monitoring the
lower number of traffic metrics.
• Efficiency: The efficiency of an XAI method can be
defined as how much time the XAI method takes
to generate an explanation. This metric is important
because it measures the applicability of the XAI method
in real-world systems since it is preferable that the
explanations are generated quickly rather than slowly
for practical purposes. As the ultimate goal is to aid
security analysts, the expectation is to be able to
generate accurate XAI explanations in real-time to detect
intrusions in a timely manner.
• Stability: The stability metric measures how consistent
the XAI method is in generating its explanations. This is
measured by checking how many features are common
among different running trials with the same conditions.
Based on such stability test, an XAI method with higher
stability can be trusted more by the security analyst in
the network intrusion detection process.
• Robustness: The robustness of an XAI method can be
defined as the ability of that XAI method to generate
the same explanations under small perturbations in the
intrusion features. Such perturbation can be due to
computational errors or an adversarial attack. For this
work, we adapted the adversarial model of the work [24].
This adversarial model consists of training an extremely
biased model that will rely only on one feature to base
its prediction on and training another model with all
the features plus a new feature that is engineered to
fool the XAI explanation method. Based on such two
trained models, XAI method under test will generate
an explanation of a normal sample that is convincing
to a security analyst while in reality the real sample
was hidden from the XAI method. This can compromise
the integrity of the framework via disconnecting the
explanation from the underlying behavior, and thus
disguise an attack as normal network traffic.
• Completeness: The completeness characteristic of an
XAI method refers to the ability of the XAI method to
provide a correct explanation for every possible network
traffic sample, including corner cases. If the XAI method
is not complete, this opens the door for the intruders to
exploit and trick the XAI method to create degenerated
results. We emphasize that if an XAI is complete, it
automatically becomes more robust (i.e., its reliability
for the end user is increased because it can detect
whether the explanation is valid). Nonetheless, while
the measure for completeness is by checking that every
sample has a valid explanation, the robustness metric in
this work refers to how resistant an XAI framework is
when facing an adversarial attack.
We explore the aforementioned six evaluation metrics
on two popular black-box XAI methods. These two XAI
methods are LIME [25] and SHAP [26]. LIME and SHAP are
well-known and widely-used XAI techniques by the network
intrusion research community [23], [24], [27], [28]. LIME
is used within the scope of local explanations, and is based
on linear approximation generated by creating perturbations
around the sample to understand the behavior of the inputs for
a given decision generating rules on how that model behaves
on that sample. On the other hand, SHAP has both local and
global scopes. This method is based on the Shapley value
concept from game theory where it measures the importance
of each feature by calculating its corresponding Shapley
value. Then, if the AI model performs the same without such
a feature, it will have a low importance.
We explain the step-by-step process for each one of our six
evaluation metrics (descriptive accuracy, sparsity, efficiency,
stability, completeness, and robustness) to generate our XAI
evaluation metrics and their results.
We evaluate our framework on three network intrusion
datasets with different characteristics. The first dataset is
the recent RoEduNet-SIMARGL2021 dataset [29] collected
from the SIMARGL project (supported by the European
Union). It contains realistic network traffic along with
features that can be calculated from live traffic, which makes
the dataset highly usable for network intrusion detection
systems. The second dataset is CICIDS-2017 [30] which
is a benchmark intrusion detection dataset created by the
Canadian Institute for Cybersecurity at the University of
Brunswick in 2017 with different attack profiles. The final

II. RELATED WORK
Existing Efforts in Leveraging XAI for IDS: The
survey [33] offers an overview of ongoing efforts in
introducing a framework for the development of Explainable
AI-based Intrusion Detection Systems (XAI-IDS),
accompanied by a taxonomy for standardizing concepts.
This survey builds upon the distinctions between black-box
models (opaque models) and white-box models (transparent
models), examining their trade-offs in terms of explainability
and performance.
In this context, several recent works have begun exploring
the utilization of Explainable Artificial Intelligence (XAI)

[16] employed decision tree algorithms to extract rules in
IDS using the NSL-KDD dataset. The work [17] incorporated
LIME to provide local explanations for an SVM model in
the IDS. The authors in [18] integrated the CIA principle
to enhance the explainability of AI models using the
CICIDS-2017 dataset. In summary, most of these efforts can
be found in [33], which maps the current state-of-the-art
works in the field. The paper [33] also proposes an

‘pre-processing phase’ which involves taking a raw dataset as
input and outputting a high-quality dataset. The second step in
the framework is the ‘modeling phase’ where the high-quality
dataset is used to generate explanations for the results. The
last step is the ‘post-modeling explainability Phase’ which is
characterized by the user interface that can be customized for
its audience.
There are also other notable related works, including
the work [20] that introduces a new framework named
OW AD (Open World Anomaly Detection), which pioneers
in addressing normal concept drift in deep learning-based
models. Similarly, the work [31] contributes a new framework
called DeepAID, aiming to address the limitations of
unsupervised DL-based anomaly detection systems. Shifting
the focus to attacks in camera network systems, the work [32]
showcases an online (i.e., real-time) anomaly detection
system for network intrusion detection. Table 1 shows the

XAI Evaluation: There are few works that considered
evaluating XAI methods for network intrusion detection [23],
[24]. The work [23] has established six metrics to evaluate
XAI methods for applying deep learning in security. They
used these metrics to evaluate black-box and white-box
XAI methods for two datasets Malware Genome Project
and CWE-119. This paper compared the performances of
white-box explanation methods (IG, GRADIENTS, and
LRP) [23] and black-box XAI methods (SHAP , LIME, and
LEMNA). Although the realm of [23] lies in the security
domain, their focus was on different subsets of the security
domain. In particular, the CWE-119 dataset consists of
malicious code samples that take advantage of improper use
of memory buffer which can help programmers in finding
vulnerabilities in code implementation. On the other hand, the
Malware Genome Project contains and systematizes several
Android malware samples. Therefore, these applications
differ from our work’s focus on network intrusion detection.
The paper [24] has developed an adversarial attack on LIME
and SHAP to test their robustness. The main idea is to
train two different models, one that is extremely biased
and its decision is based on one feature, and another one
that is innocuous with an extra ‘unrelated’ feature that is
inserted to have a direct correlation with the prediction
results. Then the innocuous prediction is passed into LIME
and SHAP to deceive them to create seemingly correct
explanations although the associated sample is an attack. In

III. THE PROBLEM STATEMENT
We now provide the main preliminaries for network intrusion
detection, the challenges of black-box AI, the need for XAI,
and the challenges in evaluating XAI methods when applied
to network intrusion detection.
A. NETWORK INTRUSION TYPES
There are several common network intrusion types. In our
work, we consider the main network attacks in the common
MITRE A TT&CK framework [34]. Thus, the network traffic
can be divided into the following categories:
Normal traffic: is the regular traffic collected from the
network.
PortScan (PS) / Network Service Discovery [MITRE
A TT&CK ID: T1046]:It is an intrusion in which the attacker
aims to make recognizance of the victim’s computer. It is
often used as the first step of an attack to search for vulnerable
points and possible entrance ports. The functionality is to send
a connection solicitation to the victim without ever finalizing
the connection. However, for this attack, the solicitations are
sent to various ports and the ones that send a message back
are mapped as possible entrance points [35].
Denial of Service (DoS) / Network Denial of Service
[MITRE A TT&CK ID: T1498]: It is a type of attack
where the objective is to render the target unavailable for the
network. One popular example of such an attack is where the
attacker keeps sending solicitations to connect with a server.
However, when the server accepts the solicitation and sends
an acknowledgement to the origin expecting its response it
never receives a response. As a result, the memory for these
open communications is left open and fully consumed until
the server becomes unavailable. We refer to [36], [37] for
detailed classes of DoS attacks.
Brute Force [MITRE A TT&CK ID: T1110]: It is an
attack in which all password possibilities are attempted by
the intruder in order to break into the victim’s network. This
attack is often paired with the knowledge of the most common
used passwords. It can become effective in cases in which a
user has a weak or a common easy-guessing password [36].
Web Attack / Initial Access [MITRE A TT&CK ID:
TA0001, T1659, T1189]: It is a class of attacks performed
via the web in which the attacker exploits web vulnerabilities.
For example, an attacker may gain access to the application’s
underlying instance or container by exploiting a public-facing
application, using a software bug, misconfiguration, or glitch.
The web attack can also include attacks such as the Drive-by
Compromise [38], however web attacks (e.g., SQLi, XSS)
typically do not provide initial access to a remote server [34].

Infiltration / Initial Access [MITRE A TT&CK ID:
TA0001]: This attack occurs when someone tries to get
initial access to a system or application. Such class of attacks
consist of a myriad of techniques as targeted spearphishing
and exploiting weaknesses on public-facing web servers. The
foothold gained by this attack can range from a simple change
of password to continue access through valid accounts and
external remote services.
Botnet / Compromise Infrastructure [MITRE
A TT&CK ID: T1584.005, T1059, T1036, T1070]: It
is an automated class of attacks which is performed by
hijacked devices executed remotely by the attacker in
which scripts (bots) mimic human behaviour and duplicate
it [39]. This scripted technique allows scalability and easy
deployment making it an ideal tool to touch multiple attack
points simultaneously. Thus, Botnet is a very common
network attack type.
Probe Attack/ Network Scanning or Surveillance
[MITRE A TT&CK ID: T1595]: Probe attacks are often
the preliminary stage of a more comprehensive attack. These
attacks involve scanning a network to gather information or
find known vulnerabilities [40]. An attacker with a map of
machines and services that are available on a network can use
this information to look for exploits. We emphasize that while
port scanning is a form of probe attack, not all probe attacks
are port scans. Some might target specific vulnerabilities or
use different methods. Examples include ping sweeps [41],
and DNS zone transfers [42].
Remote to Local Attack (R2L) [MITRE A TT&CK ID:
TA0001, T1110,T1078]: R2L is class of attacks in which
an attacker (who can send packets to a machine over a
network but does not have an account on that machine) gains
unprivileged access as a user of that machine (i.e., initial
access). Once the attacker has user-level access, they may
attempt to escalate privileges to gain control over the entire
system (i.e., U2R attack).
User to Root Attack (U2R) [MITRE A TT&CK ID:
TA0004, T1078]: User to Root attack is a type of exploit in
which the attacker starts out by accessing an unprivileged user
account on the system (via sniffing passwords, a dictionary
attack, or social engineering) to exploit some vulnerability
to gain root access to the system. This can be extremely
detrimental as it can allow the attacker to manipulate the
system as a root user or an administrator. Note that R2L is
a necessary preliminary for Privilege Escalation (i.e., U2R).
B. INTRUSION DETECTION SYSTEMS
The increasing sophistication of network attacks poses a
significant threat to critical infrastructure across various
sectors [43], [44]. Consequently, IDS plays a crucial role in
safeguarding computer network systems against malicious
activities, whether initiated by internal users or external
infiltrators [45]. Traditional IDS designs typically rely on the
assumption that an intruder’s behavior will deviate noticeably
from that of a legitimate user, making many unauthorized
actions detectable [46]. With recent advancements in AI over
the past decade, this design paradigm has paved the way
for the development of AI models capable of automatically
detecting network intrusions [47].
C. SHORTCOMINGS OF BLACK-BOX AI MODELS
While AI models have greatly automated intrusion
detection, they possess a black-box nature due to the
intricate relationships between features that underlie their
decision-making processes. This inherent complexity makes
it challenging to comprehend how and why these models
arrive at particular results. The black-box issue is pervasive
across many AI models, including random forests and deep
neural networks. Despite their high predictive accuracy
in IDS, explaining the rationale behind their behavior,
especially when errors occur, can be elusive. This becomes
especially critical in safety-sensitive applications such as
network security through IDS. Consequently, there is a
growing motivation to provide explanations for the decisions
made by AI models in the context of IDS [48].
D. MAIN CATEGORIES OF EXPLAINABLE AI (XAI)
Explainable AI is a relatively recent research field that has
been developed to address the aforementioned black-box
nature of most AI models. The explainability in AI can be
considered as the collection of features of the interpretable
domain that have contributed to a given example to produce
a decision by the AI model in a task (e.g., classification or
regression). Without loss of generality, XAI can be divided
into the following subareas: (1) XAI techniques that explain
the behavior of an AI model globally (on many data instances)
or locally (on specific instances), (2) XAI techniques that
are model-agnostic (can explain any AI model generally) or
model-specific (tailored for explaining specific AI models),
and (3) XAI explanation methods which can be either the
creation of a surrogate model (i.e., the creation of a simple
model to explain a complex one) or the creation of a feature
importance list for the global AI model (i.e., this is based on
Shapley values, or other available methods).
E. BENEFITS OF XAI FOR NETWORK IDS
The output generated by the current AI-based IDS often
poses challenges for human analysts, as it is not readily
interpretable. Consequently, analysts are required to sift
through a vast volume of logs to identify abnormal behaviors.
Moreover, they lack the means to pinpoint issues within AI
models for improvement. Hence, in domains such as network
intrusion detection, achieving both high accuracy in results
and comprehensible explanations for AI algorithms is of
paramount importance. Security analysts must understand
the decisions made by AI systems and build trust in their
capabilities. Therefore, XAI frameworks play a vital role in
assisting analysts by providing techniques that elucidate AI
decisions, facilitating efficient investigations, and ultimately
saving time for the human security analysts.

F. CHALLENGES OF XAI FOR IDS AND NEED FOR
EVALUATING XAI
There are several challenges in applying XAI for network
intrusion detection. Overall, there is not a black-box XAI
technique that can generate explanations that address all six
evaluation metrics perfectly (as shown in the results of this
work in Section VI and in the work that defined the evaluation
metrics [23]). The current challenges can be categorized as
shown below:
• Lack of Transparency: AI models that are designed
for network intrusion detection have a black-box
nature. This represents a hard challenge when it
comes to interpretation and understanding. This lack
of transparency poses a problem in network security
because it makes it hard for security analysts to audit
and protect systems from possible attacks.
• Limited XAI Application in Network Security: Due
to unique challenges of network intrusion detection [49],
there is still a lack in developing interpretation methods
for network intrusion detection systems. This is in
contrast to other systems where there are already
more XAI methods developed (e.g., text analysis and
computer vision). This situation hinders the application
of XAI methods in the network security domain.
• Accuracy and Robustness: Besides being accurate,
XAI methods applied to network security systems need
to satisfy extra requirements, such as providing complete
and robust explanations. Therefore, by having complete
and robust explanations, XAI methods would be more
reliable which can ensure their effective application in
network security.
• Evaluation and Comparison: There is a pressing need
for developing evaluation criteria in order to evaluate
XAI methods and compare different XAI methods in
the network intrusion detection field [50]. Such criteria
should cover network security domain requirements
(e.g., stability, robustness, reliability, and efficiency), as
well as general properties of machine learning models
(e.g., accuracy, transparency, and explainability).
IV. FRAMEWORK
The main goal of this work is to provide an XAI evaluation
pipeline that derives important metrics for testing each XAI
method. Our framework can help in choosing efficient XAI
methods that can help security analysts better understand
the features of the network traffic and the decisions of the
intrusion detection AI models to prevent different types of
intrusions on the network under their management. The
components of our framework are detailed below.
A. HIGH-LEVEL XAI EVALUATION PIPELINE COMPONENTS
In a high-level fashion, our framework starts by loading
well-renowned network intrusion datasets that contain traffic
logs from the network of interest. After collecting the
network’s data, our framework feeds such data into different
black-box AI models where these models detect intrusions

and normal traffic via constructing a multi-class classification
problem. In this classification problem, each class represents
one possible network intrusion (e.g., denial of service,
port-scanning, and brute force attacks). After predicting
traffic instances using the black-box AI model, the following
step is to pass these predictions into XAI methods to
generate the explanations of the instances and the associated
predictions. Then, our framework evaluates these XAI
methods by leveraging the six XAI evaluation metrics (i.e.,
descriptive accuracy, sparsity, efficiency, stability, robustness,
and completeness).
B. LOW-LEVEL XAI EVALUATION PIPELINE COMPONENTS
We now explain the low-level components of our XAI
pipeline. The different components (shown in Figure 1) are
explained below.
Network Intrusion Datasets: The first component in
our pipeline is loading a network intrusion dataset from
the database as a starting point. In our work, we use
three popular network intrusion detection datasets which
are RoEduNet-SIMARGL2021 [29], CICIDS-2017 [30], and
NSL-KDD [21] datasets.
Black-box AI Models: Once the preprocessing of the
dataset is complete, we train the black-box AI models
where we perform splitting of the data with a split of 70%
for the training while leaving the unseen 30% for testing
purposes. For this component, we have built seven popular
AI classification models including random forest (RF),
deep neural network (DNN), adaptive boosting (AdaBoost),
multi-layer perceptron (MLP), k-nearest neighbors (KNN),
support vector machine (SVM), and LightGBM. For training
each model, we choose its specific parameters to ensure the
best possible performance (see Section V).
AI Models Selection Criteria: The AI models considered
in this work were chosen for the following reasons: The
first reason is that they are ubiquitous in many similar
works that focus on IDS (e.g., [21], [36], [37]). The second
reason is to study the effect of XAI-based feature selection
on the performances of AI models in IDS, which enables
us to compare our methods with prior works on the three
considered datasets [21], [36], [37]. In this manner, we
can help keep consistency with the literature in IDS when
comparing different models paired with the XAI techniques.

XAI Methods: After constructing the black-box AI
models, we use XAI methods to explain such models. For this
purpose, we leverage two popular black-box XAI methods
which are LIME [25] and SHAP [26]. These methods cover
both global and local scopes in evaluating black-box AI
models. Furthermore, these techniques are post hoc where
they are used after the AI model is trained and its predictions
are generated. Thus, these methods are model-agnostic
methods and can be used to evaluate diverse sets of black-box
AI models. Therefore, LIME and SHAP are well-known
XAI techniques for evaluating black-box AI models [23]. We
reemphasize that SHAP applies the concept of Shapley value
from game theory to score and classify the most important
features in a given AI’s decision while LIME uses surrogate
linear local models to approximate the global AI model and
derive explanations on a given sample (here, network traffic
instance or sample).
Note that although LIME was originally made for local
explanations, we leveraged it to work with the scope of global
explanations (as shown in Tables 7, 10, 11, and 13). Our
modification can be described as follows. We select how
many samples we want to analyze and for each sample, LIME
generates a local explanation with the associated scores for
each feature. For each feature, we aggregate these scores and
store them in a list that is constructed for that feature. For
each iteration, we sum the absolute values of those scores for
each feature, and at the end, we average all the results by
the number of samples used. Finally, we rank the different
features where the features with the highest scores would
be selected as the most influential ones. We also refer to
subsection E.1. for a step-by-step explanation.
Rationale of Choosing SHAP and LIME: The choice
of these two frameworks for our pipeline is due to
single-feature explainability methods like partial dependence
plots (PDP) [51], individual condition expectations plots
(ICE) [52], and leave one column out (LOCO) [53] lack the
direct ability to capture interactions between various features.
This limitation makes it progressively challenging to maintain
local model fidelity. Conversely, SHAP and LIME address
these constraints of single-feature models effectively. The
aforementioned popularity of these two methods for IDS is
another reason for focusing on them.
XAI Evaluation Metrics: Our framework mainly seeks to
evaluate different XAI methods by generating six evaluation
metrics for each XAI method. These six metrics are
descriptive accuracy, sparsity, efficiency, stability, robustness,
and completeness. First, descriptive accuracy measures the
drop in the AI model’s accuracy when the top most influential
features (generated by XAI methods) are absent. Second,
sparsity measures whether the explanation is ‘divided’ among
the features or not (i.e., if many features are influential, then
the XAI method is not sparse). Third, stability measures
the level of trust in a given explanation. In other words, if
the XAI explanation is the same under many trials within
the same circumstances, then the XAI technique is stable.
Fourth, efficiency is related to the time the XAI method
takes to produce its explanations (e.g., a method that takes
too long time to produce explanations is not efficient). Fifth,
robustness is how resistant the XAI method is when facing
a malicious actor that is trying to attack its integrity (i.e.,
an attacker might disguise an attack by generating fake (or
degraded) yet plausible explanations to avoid detection).
Finally, completeness measures the ability of the XAI method
to cover every instance. For instance, an XAI method
that provides a correct explanation under different corner
instances is complete.

C.5. Robustness Step-by-Step
Prerequisites: The algorithm from the work [24].
For each dataset (CICIDS-2017, NSL-KDD, and
RoEduNet-SIMARGL2021), we run the Robustness
experiment as follows:
1) We train the adversarial model, and the biased model.
The objective is to decouple the original explanation
from the post hoc XAI explanation (by SHAP or
LIME).
2) For the adversarial model, we use the top- k (with k= 6)
intrusion features for the unrelated feature. Meanwhile,
for the Biased model, we only use the Biased feature.
3) We use SHAP and LIME to check if the Biased feature
indeed appeared as the top feature for the biased
model. Also, for the adversarial model, we check if the
unrelated feature and the biased feature appear in the
top 3 positions (features).
4) To generate the occurrence graph, we run the
Robustness metric for 1000 samples. For each run, and
each model (adversarial and biased), we stack the top
3 features in a bar graph.
5) We then analyze the occurrence of each feature of each
model in the text. The biased model is prerogative
biased, so the top-1 feature likely is the biased one.
6) We look at the adversarial model and check if the
unrelated and the biased features are at the top 3
features. The presence of the unrelated feature in rank
higher than the biased feature means the explanation
was hijacked.
7) Sensitivity graph: We also use the work of [23]
to generate such a sensitivity graph. Considering all
datasets, we train OOD classifier models and extract
their F1 scores. Such scores are used as the X-axis, then
the explanation is run for the adversarial models, and
the occurrence of the biased feature appearing as 1st in
the SHAP or LIME explanation is tallied and used as
the Y -axis.
Discussion: We stress that robustness’s main point is
showing that such an adversarial attack on XAI methods
(explained above) is possible. However, we do not enter
the merit of actually performing it in the sense of how to
break into a system and switch the correct AI model for
the adversarial one used for the explanation to generate the
disguised explanation. Therefore, the attacker exploits the
fact that the LIME and SHAP are post hoc XAI methods.

table that is generated to test trust in XAI explanations.
The stability experiment generates top features several times
for each XAI method and checks the intersection among
these features from different trials with the same conditions
(see Tables 11-12). Fifth, for robustness we adapted the
code from [24] and generated an adversarial model that
decoupled the sample from its explanation and we tested
whether we could generate false predictions while providing
convincing explanations on them (e.g., an attack on AI
model to predict a network intrusion sample as normal while
providing convincing XAI explanation on such decision) (see
Figures 11-12). Finally, for completeness, we test whether
XAI techniques can achieve completeness or not (covering
true explanations of all network traffic instances, including
corner cases). For instance, if a perturbation is caused by the
top features changing its explanation, but not changing its
predicted class, we can not trust such an explanation. Thus,
our completeness figures and tables (see Tables 14-16 and
Figures 13-15) measure whether the most influential features
change the outcomes when perturbed enough.
C. PRELUDE - FEATURE SELECTION
Before presenting detailed evaluation results, we first explain
how we obtained the importance scores of intrusion features
since such importance will be used during our different
experiments. For each model, we generated a SHAP global
explanation and a LIME global explanation (shown in
Appendix B)2.
For descriptive accuracy and sparsity evaluation metrics, a
global explanation was generated after running each AI model
for each dataset. Then, we stored the list of the explanations
and repeated the experiment by removing top-k features (k =
5 for RoEduNet-SIMARGL2021, k = 20 for CICIDS-2017,
and k = 20 for NSL-KDD) from the dataset in descriptive
accuracy and sparsity cases by using feature’s importance
value to generate the results. In the case of stability, we
generated the explanations similar to the above-described
way, but for p different trials (in this study, we have p
= 3) to evaluate which top-k features intersect (k = 5 for
RoEduNet-SIMARGL2021, k = 20 for CICIDS-2017, and k
=20 for NSL-KDD). When evaluating robustness, the feature
extraction method is local because the experimental setup
consists of evaluating each explanation individually when
performing the integrity attack. For completeness, similar
to robustness, the feature extraction method is local, but
this time these features are used to evaluate the AI model’s
classification and associated explanation when perturbing the
top-k features (k = 5 for RoEduNet-SIMARGL2021, k =
5 for CICIDS-2017, and k = 5 for NSL-KDD). Lastly, the
efficiency experiment does not require the extraction of any
features. However, we need to generate them to calculate
the computational time to run SHAP and LIME in different
scenarios.
Having explained the main experimental setups, datasets,
and XAI evaluation metrics, we next provide an in-depth
metric analysis that has all our evaluation results.

B. SPARSITY
We then evaluate the sparsity of XAI methods which
measures the relevance of feature importance scores (given
by the XAI method) for different intrusion features. This is
done by comparing how many features are below a certain
threshold τ (values from 0 to 1). Here, the threshold is the
defined small predefined steps of 0.1 that range from 0 to
1. For example, suppose that the threshold value is given by
τ → 0 and there are 19 out of the 20 intrusion features that are
below or equal to this threshold. Then, this means that there is
only one feature that has an extremely high influence on the
AI model’s decision, and therefore the sparsity is high. From
a graphic-wise point of view, it means that we have more area
under the curve for sparsity, as can be seen in Table 10. The
intuition here is the higher the area under the curve (AUC), the
lower the number of top features needed by the XAI method
to provide a good explanation.
Axis Explanation: The values of features in the X-axis
in Figures 4-5 are thresholds that increase in steps of 0.1,
from 0 to 1. Thresholds are values that we manually set to
compare with the LIME or SHAP importance scores to count
how many features are below the threshold at a given time.
We stress that the higher the importance score, the higher
the feature significance from the point of view of the XAI
technique. For example, if we analyze a total number of 10
features and 3 out of 10 features have scores less than 0.5,
we will have a sparsity score of 0.3 when the threshold is
0.5. Since LIME and SHAP importance scores are normalized
using min-max, we guarantee that this metric equals one when
the threshold value is one because all features will have at
most the importance score of one. We also emphasize the

D. EFFICIENCY
We next evaluate the efficiency of different XAI methods.
Recall that the efficiency experiment does not require the
extraction of any features, but it generates them to evaluate
the computational time it takes to run SHAP and LIME in
different scenarios. Table 13 shows such efficiency results
for SHAP and LIME XAI methods for the three network
intrusion datasets. We also show the efficiency from global
and local scopes. Globally, one of the main differences
between LIME and SHAP when looking at the efficiency
metric (shown in Table 13) is the consistency of LIME for
all AI models. In all models but KNN, LIME has roughly the
same computational time. On the other hand, while SHAP
performs better for LGBM, RF, and DNN models, SHAP’s
efficiency drops for SVM and MLP and it plummets for ADA
and KNN. Thus, it is non-practical to use MLP and KNN for
real-time IDS. In the local scope, Table 13 shows that SHAP
is more efficient than LIME for all of the seven AI models.
Given these results, we have the following
recommendations from a computational efficiency
perspective: (i) the best choice for SHAP is to pair it
with LGBM, RF, or DNN for global explanations, (ii) the
usage of SHAP is better than LIME for local explanations,
and (iii) adapting LIME for global explanations is more
efficient compared to SHAP .
E. ROBUSTNESS
To test the robustness of XAI methods, we are adapting the
method proposed in [24] for our network intrusion detection
application domain. This method consists of generating
an adversarial model and a biased model to decouple
the prediction from the post hoc XAI explanation. For
each dataset (RoEduNet-SIMARGL2021, CICIDS-2017, and
NSL-KDD), we use the top intrusion features for training
such models. As an example, to analyze a denial of service
(DoS) sample for the CICIDS-2017 dataset, we use only the
flow duration feature for constructing the extremely biased
model (as shown in Figure 6a). In this example, we also
create an unrelated fake feature that correlates with the biased
model prediction for the adversarial model (as shown in
Figure 6b). The flow duration feature was chosen because
it is one of the main flags for a DoS attack. Hence, if
this experiment is successful it means that an attacker can
deploy a DoS attack and trick the security analyst by showing
him a fabricated convincing explanation for normal traffic
although it is a DoS attack. Thus, the attacker can hide and
compromise the XAI explanation integrity. We also conduct
a similar experiment for the NSL-KDD dataset focusing on
the dst_host_same_srv_rate feature which is identified as the
most influential attribute in this dataset [24].
We first show the percentage of samples for which each
feature appears in the top 3 features (according to LIME and
SHAP rankings of feature importance) for both biased and
adversarial classifiers. Figure 8 shows this percentage for the
CICIDS-2017 dataset. Note that the biased model (Figure 8a)
always has the biased feature as the top feature as expected.
Meanwhile, the adversarial model (Figure 8b) shows that the
unrelated feature is the most important one while the biased
feature has only a few occurrences as the second or third
feature. Similarly, Figure 9 and Figure 10 show the results
of the above experiment for RoEduNet-SIMARGL2021 and
NSL-KDD datasets, respectively.
Bar Plots: Comparing the bar plots generated for SHAP
for the three datasets, we see that the biased feature dominates
the first place in all occurrences (see Figures 8a, 9a, and 10a).
The difference lies in the second and third feature columns
for the adversarial model in Figures 8b, 9b, and 10b. For
all three datasets, although these figures show that the
unrelated feature massively appears as the top feature, there
is a variation in how much the biased feature appears in
the second or third column. Since this is the feature the

G. STATISTICAL ANAL YSIS
We believe that a statistical analysis would bring the
validation needed to support our findings. Hence, we chose
to apply the non-parametric Wilcoxon signed-rank statistical
test to the three datasets used in this work. The rationale
behind our choice is that our datasets do not have a
normal distribution. First, we prepare seven models (i.e.,
this will generate 21 p-values for each pair combination of
models). Then, we apply the significance test using k-fold
cross-validation and their accuracy scores for each model.
The result will generate two samples, one for each model (for
the two models being compared against each other). Later, we
applied the Wilcoxon test to obtain the difference between
both samples. If they differ from each other in a significant
matter, one can imply that there is significant evidence that
one model is more accurate than the other. The algorithm
ranks which differences have the highest absolute difference
value. Finally, we check whether the calculated p-values are
lower than 0.05 to reject the null hypothesis (i.e., there is
no difference in the performance of the two models being
compared). We have added our statistical analysis results
(which are shown in Table 17).

I. EVALUATING PERFORMANCE OF CNN
We finally apply CNN to our performance metrics and
the same XAI evaluation metrics as we did with the other
models. We stress that the work [23] used such models
because their datasets consist of code fragments and infected
documents (e.g., PDFs). In particular, this scenario is perfect
for CNN and RNN since the data has an intrinsic positional
relationship, and the order of information matters. Thus, it
benefits from the ways that these models work.
Y et, the representation problem is usually solved because
humans pre-define the characteristics of the tabular data.
Since relationships between features in tabular data are

VII. LIMITATIONS AND DISCUSSION
(1) Importance of Our XAI Framework for IDS: In
today’s world of exponential information growth, it is
natural that network attacks would become more frequent
(e.g., see the recent study by the Center for Strategic &
International Studies (CSIS) [68]). Although IDS has evolved
throughout the years, security analysts are responsible
for double-checking possible attack occurrences that are
generated faster than they can be analyzed. Therefore, having
accurate XAI-based intrusion detection systems can help
solve such a problem. Our framework proposed in this work
helps to evaluate these XAI-based systems thoroughly to
deploy them for network security.
(2) Exploring Our XAI Evaluation Framework
on Other Benchmark Datasets: In this work, we
focused on giving a complete treatment of our XAI
evaluation framework on three state-of-the-art network
intrusion detection datasets (CICIDS-2017, NSL-KDD, and
RoEduNet-SIMARGL2021). However, one fruitful direction
for related future research is to explore the efficiency of
our XAI evaluation framework on other network intrusion
detection benchmark datasets, including UNSW-NB15 [69],
UMass [70], and vulnerability-based datasets [71], and
among others.
(3) Dataset Analysis: The experiments allow us to extract
a few interesting conclusions about the datasets used. First,
we conclude that the models achieved better explanations for
the NSL-KDD dataset than the other two datasets. We can
speculate that each NSL-KDD feature column information
tends to be unique, and it does not overlap or have a higher
correlation with other columns. Hence, models tend to find
clear relations and patterns with a lower number of features
for NSL-KDD. As a consequence, they can provide better
XAI-based explanations. Second, we observe that NSL-KDD
does not have fewer features that can bias the models used (as
explained in the next subsection named ‘‘Effect of Bias of Top
Intrusion Features’’). Another possibility is that it could also
mean that RF, LGBM, and KNN can produce high accuracy
for only a handful number of features. However, this is a less
likely option since this is only true for CICIDS-2017 and
the RoEduNet-SIMARGL2021 datasets. Third, the size of
datasets does not seem to correlate directly with performance,
even when there is a significant difference in the number of
features of the datasets (i.e., CICIDS-2017 has 78 features,
RoEduNet-SIMARGL2021 has 29 features, and NSL-KDD
has 41 features), the same models in CICIDS-2017 do not
perform well for the NSL-KDD. Therefore, we could derive
that the original number of features in the dataset is not the
key factor for explanations.
(4) Reliability of Current Black-box XAI Methods:
Although SHAP and LIME can be used for auditors when

consistency of XAI results under a proper selection of AI
models. Overall, all these observations and suggestions can be
used to pave the way toward the end goal of having a powerful
black-box XAI tool for network IDS.
(6) Incorporation of LEMNA in Future XAI
Evaluations: While our E-XAI framework currently
focuses on SHAP and LIME, the exclusion of other
XAI methods like LEMNA presents a limitation in our
study. LEMNA, known for its effectiveness in unraveling
complex nonlinear data relationships, could potentially offer
valuable insights that are not captured by SHAP and LIME.
However, its limited user accessibility and adaptability,
particularly when compared to SHAP and LIME, along with
its less extensive testing, raise concerns about its reliability
and overall performance in network intrusion detection.
Additionally, LEMNA ’s approach, which shares similarities
with software fuzzing methods, introduces certain risks that
need careful consideration. These risks akin to those found
in software fuzzing methods that incorporate random noise
into data inputs, which may pose risks such as generating
false positives or negatives, potential overfitting issues, and
susceptibility to adversarial attacks due to their exploratory
nature. Such inherent randomness can deliver unreliable
results. Future research should aim to include LEMNA and
similar methods, addressing these challenges to provide a
more rounded evaluation of XAI tools for network security.
(7) Addressing Feature Bias in AI Models: Concerning
overall features, prior works show that some features
demonstrate bias in the dataset generation. In particular,
“Destination Port” has been revealed to be a sign of bias [72]
where it can have a contaminating effect when included
in AI network intrusion detection models. Similarly, we
may infer that TCP_WIN_SCALE_IN may have the same
contaminating effect for the RoEduNet-SIMARGL2021
dataset. We emphasize that our decision-making XAI
explanation and feature importance do not depend on a
single feature. Thus, even if some features are biased,
the majority should compensate for such a bias. Another
possibility for accommodating this is adding a warning with
the XAI explanation if one top feature is from these two
biased features. Incorporating warnings or indicators in XAI
explanations about potentially biased top features could help
users better understand and interpret the results, leading to
more informed decision-making.
(8) Time Performance Variations Among XAI Methods
and AI Models: Our analysis reveals significant differences
in the time efficiency of various AI models when coupled
with XAI methods like SHAP and LIME. LIME shows
general time efficiency across different models but falls short
with KNN, while SHAP pairs better with models such as
LGBM, RF, and DNN, but is less efficient with MLP , ADA,
and KNN. This highlights the crucial need for selecting the
appropriate combination of AI models and XAI methods
based on specific requirements and real-time operational
demands. Future iterations of our proposed E-XAI framework
should aim to optimize this aspect, ensuring that the chosen
XAI methods not only provide accurate and understandable
explanations but also do so within the time constraints typical
of real-world network intrusion detection scenarios.
VIII. CONCLUSION
The end goal of a security intrusion detection tool is to
serve as a shield or as a prevention mechanism against
intruders. The usage of AI can help in having these tools
automated. Thus, there is a pressing need to find new
solutions that can effectively explain AI intrusion detection
methods. This paper presented an end-to-end framework for
the evaluation of black-box XAI techniques for network
intrusion detection tasks. Our framework evaluated both
global and local explanations for XAI methods for network
IDS. We analyzed six different evaluation metrics for two
popular black-box XAI techniques (SHAP and LIME).
These six metrics are descriptive accuracy (for checking
trade-offs between XAI explainability and intrusion detection
accuracy), sparsity (for measuring the correlation between
different intrusion features given by the XAI method),
stability (for checking the consistency of the XAI method in
generating its explanations for traffic instances), efficiency
(for measuring the applicability of the XAI method in
real-world systems), robustness (for checking the ability
of XAI method in generating the same explanations under
adversarial attacks), and completeness (for testing the ability
of XAI method in providing a correct explanation for every
possible network traffic sample, including corner cases).
We evaluated our XAI evaluation framework via extensive
experiments using three popular network intrusion datasets

APPENDIX A AI MODELS AND HYPER-PARAMETERS
We now provide the hyperparameters of our different AI
models considered in this work.
A. AI MODELS AND HYPERPARAMETERS DETAILS
Deep Neural Network (DNN): The first classifier is a deep
neural network (DNN). The architecture of this classifier
consists of an input layer with the count of neurons
corresponding to the used number of features, and the
rectified linear unit (ReLU) activation function. This is
followed by a dropout layer with the dropout set at 0.01,
a hidden layer with a size of 16 neurons, and the ReLU
activation function. The setup closes with a ‘‘softmax’’.
The loss function was set to the ‘‘categorical_crossentropy’’
method, while the chosen optimization algorithm was
adaptive momentum (ADAM). Eleven epochs were needed
to train the model with a batch size of 1024.
Random Forest (RF): The next classifier used to
detect malicious samples in the network traffic was the
RandomForest (RF). The hyperparameters we used for this
classifier are as follows: n_estimators (a parameter that
signifies number of trees used) was set to the value of 100, the
maximum tree depth was set to the value of 10, the minimum
number of samples required to separate internal node was set
to the value of 2, and the rest were used as provided by default.

B. HYPER-PARAMETER RATIONALE
For this work, we performed hyper-parameter tuning to
maximize the performance of AI-based (or ML-based)
classifiers. The rationale behind the hyper-parameter tuning
in Appendix A is trial and error.Before applying the
post-model XAI techniques in this work, we extensively
trained and tested the same model with different parameters,
checking its performance on a standard set of well-known
metrics to evaluate each AI model for intrusion detection
classification problem. These are accuracy (Acc), precision
(Prec), recall (Rec), F1-score (F1), Matthews correlation
coefficient (Mcc) [73], and balanced accuracy (Bacc), and the
AucRoc (area under the ROC curve). For instance, taking the
Random Forest model, we first checked what tree depth starts
to get the best performance, then we experimented with the
number of nodes for that tree, the splits for each node, and
the number of trees, for example. The same is true for the
other models as well. During this experimentation phase, we
keep the better parameters found.

APPENDIX D AI MODELS’ PERFORMANCES UNDER SAME
NUMBER OF FEATURES

features, we have also tested the performances for all models
under the same features where we choose the overall top eight
features. These eight top features employed in our analysis are
detailed in Table 23 below. Our results for such an experiment
are shown in Tables 24-26 below. As shown in Table 24,
the results for the NSL-KDD dataset reveal that the Support
V ector Machine (SVM) algorithm notably excels, especially
in terms of AUCROC, thereby underscoring its exceptional
capability for in-class differentiation. This is in contrast to the
comparatively moderate performance observed in Adaptive
Boosting (ADA) and Multilayer Perceptron (MLP) across
all datasets. In a different vein, K-Nearest Neighbors (KNN)
and Support V ector Machine(SVM) demonstrate remarkable
effectiveness in the CICIDS-2017 and RoEduNet-SIMARGL

near-perfect scores across several metrics. Nevertheless, their
subdued performance in the NSL-KDD dataset suggests a
potential sensitivity to specific data characteristics.
The varying performance of these algorithms across
different datasets highlights the influence of dataset
complexity and inherent characteristics on algorithm
effectiveness. It becomes evident that while some algorithms
like KNN and RF can excel in certain scenarios, their
applicability might be limited in others, underscoring
the importance of choosing the right algorithm based
on the dataset at hand. This analysis, grounded in a
consistent methodological approach, underscores the need
for careful algorithm selection and validation in diverse data
environments to ensure robust and generalizable machine
learning models for network intrusion detection tasks.
