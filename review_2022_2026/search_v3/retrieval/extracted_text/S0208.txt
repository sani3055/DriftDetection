 Kubernetes' recent rise in popularity in cloud -native environments has led to 
new security concerns, as it brings a dynamic, decentralized and highly 
configurable architecture. Conventional rule -based security approaches can be 
ineffective in identifying advanced and zero -day attacks, especially those 
involving misconfigurations, privilege escalation, and container runtime 
vulnerabilities. An AI-based threat detection system that supports intelligent and 
flexible security monitoring by using multi -telemetry data sources such system 
calls, audit logs, and network traffic is suggested as a solution to these problems. 
The system adopts a multi -layered approach for telemetry collection, ingestion, 
feature engineering, machine learning -based detection and automated response. 
Anomaly detection based on unsupervised and semi -supervised ML approaches, 
such as IsolationForest and neural network models, is applied to detect abnormal 
patterns without the need for labeled data. The approach is evaluated in 
experiments an d shows high accuracy (0.94), recall (0.96) and an AUC (0.97). 
This suggests the method offers effective, scalable, and real -time threat 
monitoring capabilities for protecting Kubernetes-based cloud systems. 
Keywords—Kubernetes Security, AI-driven Threat Detection, Cloud Computing 
Security, Anomaly Detection, Machine Learning, Container Security

Introduction 
An evolution of Cloud Computing technology has 
become an essential part of modern computer systems 
that enable customers to access software applications 
and services over the internet in a scalable and cost -
effective manner [1][2][3]. Cloud-native architectural 
designs have developed during their existence which 
enables organizations to implement software using 
container technology and microservices across 
multiple distributed computing environments [4][5]. 
Kubernetes now serves as the primary system for 
managing containerized applications according to its 
current usage patterns [6]. The system achieved 
widespread adoption because of its capacity to 
automate deployment and scaling processes together 
with its capabilities to handle operational tasks 
throughout various cloud environments and edge

The complex Kubernetes system delivers operational 
benefits, but it creates major security vulnerabilities 
that security experts must address [7][8]. The attack 
surface includes three different system components 
that protect the system through control -plane APIs,  
workload identities and container runtime behavior 
[9]. A study of actual deployments shows that system 
errors occur frequently because system administrators 
make configuration mistakes , which create security 
weaknesses that lead to privilege escalation,  secret 
leakage and excessive system access rights 
[10][11][12]. Hackers use compromised containers to 
perform crypto jacking  and resource abuse and 
container escape which makes traditional security 
systems that rely on fixed rules and pre-existing 
signatures unable to protect current cloud -based 
systems. 
This study suggests an AI -driven [13][14], multi-
signal threat detection framework for Kubernetes -
based cloud systems in order to solve these issues. 
Machine learning  methods allow systems to create 
standard operating procedures together with the 
capability to identify security threats which include 
unknown attack methods. A detailed examination of 
system calls together with network traffic and audit 
log data allows security experts to create defensive 
systems against cyber threats. 
A strong need to automate response methods, improve 
threat detection accuracy, and guarantee robust 
security in current cloud infrastructures is driving this 
study. The key contributions are given: 
• Proposes a multi -layered AI -driven threat 
detection architecture for Kubernetes 
environments  
• Implements unsupervised and semi -supervised 
learning models for anomaly detection  
• Introduces behavior -based threat modeling for 
identifying zero-day attacks  
• Provides effective detection with enhanced 
precision, recall and AUC 
• Provides scalability and flexibility in dynamic 
cloud native environments 
A. Novelty of the paper 
The contribution of this work is to provide an 
integrated approach to using data from multiple 
telemetry signals with state -of-the-art AI -based 
Anomaly Detection methods in the context of 
Kubernetes. The approach combines information from 
the system level, network level and control plane to 
build a comprehensive model of cluster activity. It 
uses both isolation -based and DNN-based learning 
methods to detect new threats. The approach is also 
equipped with an automated response for proactively 
responding to threats. This holistic, flexible and 
scalable approach enhances threat detection and 
resilience to cyber-attacks in cloud environments. 
B. Structure of the paper 
The following is the outline for the remainder of the 
paper: AI-driven cloud security research is reviewed 
in Section II. The suggested approach, including 
detection models and system architecture, is 
explained in Section III. The results of the 
experiments and the evaluation of their performance 
are detailed in Section IV. The work is concluded and 
future research objectives are outlined in Section V. 
 
Background and Related Work  
The existing literature shows AI -based frameworks 
improving the security of Kubernetes cloud 
computing through anomaly detection, prediction, 
and response, but struggles with scalability, 
explainability, privacy, and deployment efficiency. 
A. Mahida's (2026) study provides the AI -Driven 
Observability-Based Predictive Threat Prevention 
Model (AIO -PTPM), a predictive threat prevention 
framework that weaves the metrics, logs, traces, 
system calls, RBAC transitions and network flows into 
a correlated observability fabric. By combining deep 
sequence modeling, hypergraph correlation, anomaly 
scoring and embedding -based behavioral prediction, 
AIO-PTPM can identify anomalous cluster behavior 
and predict malicious behavior. The experimental

H. Pitkar (2025) offers a solution for Kubernetes

streams, including API requests, system metrics,

demonstrate the substantial improvement in the

T. Hoßfeld (2025) introduces an AI-powered DevOps 
framework tailored for Kubernetes -based financial 
and medical systems, which combines real-time threat 
monitoring, predictive analytics, automated 
compliance monitoring and dynamic response. The 
framework uses AI and ML algorithms in the CI/CD 
pipeline and at runtime to enhance observability, 
anomaly detection and threat prediction. This 
includes behavioral analytics, unsupervised learning -
based anomaly detection and reinforcement learning -
based automated incident response. This work shows 
how AI -powered DevSecOps can detect anomalous 
network traffic, container drift, misconfigurations, 
privilege escalation, insider threats and zero -day 
vulnerabilities in real time. It also maintains 
compliance with HIPAA, PCI -DSS and GDPR 
regulations via policy automation and audit 
intelligence. The framework uses telemetry, feature 
engineering, machine learning, Kubernetes admission 
controls and security engines to create a security 
feedback loop [17]. 
S. Chitraju and G. Varma (2024) examine the 
integration of AI into cloud security solutions, 
highlighting the role of AI in improving accuracy in 
threat detection, reducing response time and 
strengthening data security in the cloud environment. 
Furthermore, the article explores several AI -driven 
tools that offer real -time security, such as IDS, 
behavior analytics, and automated threat response. 
Data privacy, algorithmic bias, legacy integration and 
the computational expense of AI technologies are 
some of the challenges faced by cloud security in 
adopting AI [18]. 
T. J. Akinbolaji (2023) aims to assess the more 
integrated level of AI and ML, especially in a real -
time threat detection system that is suitable for use in 
cloud environments. They assess the state -of-the-art 
in threat detection paradigms through a mixture of 
quantitative and qualitative approaches, and apply 
new AI approaches such as DL and RL to enhance 
threat detection efficiency and accuracy. The results 
show that compared to conventional techniques, the 
proposed model could enhance the overall threat and 
potentially harmful behavior detection accuracy by at 
least 30% [19].  
R. Vadisetty et al. (2023) explore the application of 
AI to cloud security, the benefits of AI compared to 
conventional approaches, the best ways to use AI, the 
advantages of AI in security, and the challenges 
associated with AI in cloud security.  There are still 
problems of model interpretability, adversarial 
attacks, computing power, and regulator -performed 
security compliance, but AI does enhance danger 
detection. Finally, other future research directions for 
improving cybersecurity systems with AI are 
suggested [20].

Methodology 
The method offers an AI -based approach to threat 
detection in Kubernetes systems, including collection 
of telemetry data, feature extraction and machine 
learning algorithms. It's based on real -time anomaly 
detection, behavior monitoring and alerting to 
enhance cloud systems' security, scalability and 
resilience. 
A. Architectural Overview 
Fig. 1 shows the architecture for AI -based threat 
detection in Kubernetes cloud systems is a multi -
layer, end -to-end data collection, machine learning 
and alerting approach. The Telemetry Layer involves 
real-time system, application and network data 
collection of Kubernetes entities (pods, containers, 
nodes and API servers) using eBPF, audit logs and 
service mesh telemetry. The Data Ingestion Layer 
collects data via scalable brokers (Kafka, Fluentd) for 
real-time processing. At the Feature Engineering 
Layer, data is transformed into feature vectors that 
capture statistical and behavioral  properties. The 
AI/ML Detection Layer uses models  and ensemble 
methods to identify anomalies and categorize  threats, 
enabling real -time inference and batch training. 
Then, the Detection and Decision Layer combines 
model predictions to calculate threat scores and risk 
levels. The Response Layer then invokes automated 
responses such as pod isolation, container termination 
or network policies. 
Last, the Monitoring Layer offers dashboards and logs 
for analysts to monitor threats and infrastructure. 
 
Figure 1.  Architecture of AI-Driven Threat Detection Framework for Kubernetes-Based Cloud Systems 
 
B. Telemetry Collection 
The telemetry collection layer interacts with the 
Kubernetes infrastructure to gather system and 
control-plane data. Data on control plane events is 
collected from audit logs, which log authenticated 
API calls and authorization decisions. The run -time 
behavior is captured via eBPF probes that are 
deployed as DaemonSets, allowing for efficient 
collection of system calls, process events and network 
packets at the kernel level. Additionally, system 
metrics such as CPU, memory and network traffic are 
extracted from Prometheus exporters to provide 
additional context for real -time monitoring and 
anomaly detection.

C. Feature Engineering Layer 
Here, it transforms raw telemetry streams into feature 
vectors to use for machine learning. These include 
normalization, aggregation, window creation and 
encoding events into distinct features. Audit log 
reconstruction joins API events to form sequences, to 
improve the detection system's ability to learn benign 
and malicious workloads.  Finally, features are 
periodically refreshed to cope with dynamic 
workloads, addressing concept drift and ensuring 
optimal model performance in a Kubernetes 
environment. 
D. AI Detection and Alerting Layer 
The detection layer is comprised of pre -trained ML 
models for Anomaly Detection and threat 
classification. Both unsupervised and semi -supervised 
learning methods are applied to detect deviations 
from normal patterns, as recommended in recent 
studies of cloud security. Anomalies are prioritized 
according to risk and classified as threats. The alerts 
then feed into an alerting layer, which is connected to 
native Kubernetes monitoring tools and Security 
Information and Event Management  (SIEM) systems. 
This enables rapid incident response and remediation. 
E. Behavior-Based Threat Modeling 
The threats are detected by identifying abnormal 
behavior of the cluster. These normal baselines are 
established through historical telemetry data, such as 
API interactions, resource consumption patterns and 
system calls. This behavior-based approach allows for 
the identification of new attacks, such as zero -day 
attacks and abuse of Kubernetes APIs, that are not 
detected by conventional rule-based systems. 
The key threat categories considered include: 
• Privilege escalation  
• Container escape attempts  
• Crypto jacking activities  
• Abnormal lateral movement across pods and 
nodes 
F. Anomaly Detection and Learning Strategy 
The learning model uses feature vectors extracted 
from telemetry data and tries to detect anomalies 
based on deviations from known normal behavior 
patterns. The method relies mainly on unsupervised 
and semi -supervised learning methods to facilitate 
anomaly detection without requiring large amounts of 
labeled attack data. 
Isolation-based models are used to detect anomalies in 
multi-dimensional feature spaces by identifying 
datapoints that are considerably different from the 
rest of the data. Additionally, learning -based models 
(neural networks) are employed to embed the normal 
workload behavior in a low -dimensional space and 
detect anomalies through errors in reconstruction. 
This mixed approach of statistical and learning -based 
models allows the system to detect straightforward as 
well as intricate shifts in workload behavior. The 
diversity of model types ensures detection accuracy, 
scalability across different workload types, and 
immunity to evasion in dynamic Kubernetes 
workloads. 
G. Implementation Setup and Metrics 
The proposed threat detection system was 
implemented in a virtual Kubernetes environment 
based on real-world workloads, using multiple worker 
nodes and a control plane running containerd. 
Telemetry was gathered using native Kubernetes 
components, such as eBPF -based DaemonSets for 
system call, process, and network traffic monitoring, 
audit logs for API calls, and Prometheus exporters for 
resource metrics. The detection solution was 
implemented in Python with offline model training 
on the telemetry data and serving. This allows for 
scalable and near real -time detection of threats and 
integration with Kubernetes observability and 
alerting platforms. 
Precision, recall, F1 -score, and the ROC  curve are 
some of the common categorization metrics used to 
assess the system. The assessment metrics specify two 
terms: The number of positive cases that were 
correctly recognized is called True Positive (TP), 
whereas the number of negative instances that were 
improperly categorized is called False Positive (FP). A 
True Negative (TN) is a successfully projected
