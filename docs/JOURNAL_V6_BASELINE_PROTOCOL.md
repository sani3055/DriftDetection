# Matched static detector comparison for guide-review draft

This is a post-hoc exploratory comparison specified after earlier work inspected the same deployment and event labels. It is not a prospective or independent test, and no selection using these results is allowed. It compares static detectors, not adaptive drift policies.

Use the same source archives, exact narrow chronological split, test sessions, cached strictly past-only behaviour features and event ordering as v4. Compare event-ordinal and combined-ordinal representations. Fit the existing encoder and a `StandardScaler` on the historical fitting set only. Fit Isolation Forest (100 trees, contamination 0.05, seed 42), one-class SVM (RBF, nu 0.05, gamma scale) and Local Outlier Factor (20 neighbours, novelty mode) on the same standardized historical fit matrix. Use the negative `score_samples` for all methods, with larger scores indicating greater anomaly. Set each detector's cutoff to the higher empirical 95th percentile of scores on the same earlier benign calibration records. This matches the nominal historical calibration criterion, not necessarily realized false alarm rates; ties and shifts may differ. Hold models and cutoffs fixed across all test sessions. No test labels, target adaptation or target tuning are used in fitting, scaling or calibration. Each model's test scores are computed before event labels are accessed for metrics.

Report pooled and per-session event counts, recall, false-positive rate, precision, F1, ROC AUC and average precision if both classes are present, and elapsed fit/inference time as exploratory measurements. Compare identical held-out events and use the same features and historical data, but recognize that default model hyperparameters are not tuned and scaling ordinal codes imposes arbitrary distances. Scores are not attack probabilities. The three sessions all come from one controlled deployment, and repeating representations/models does not make them independent incidents. Do not interpret the comparison as proving one detector is universally superior or as a matched comparison against an adaptive policy. Feature cache and source hashes must be validated, and prior results preserved separately.
