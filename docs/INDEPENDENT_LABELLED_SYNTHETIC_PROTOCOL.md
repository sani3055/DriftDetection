# Independent labelled synthetic transfer protocol

The target is the committed `datasets/demo.jsonl` from `katerina20/cloud-threat-anomaly-lab`, pinned to commit `535a2bd48c74ffd1652af7d092ba95b0fcb660b8` and distributed under its Apache-2.0 repository licence. Its documentation describes a cloud-neutral *synthetic* event schema, not native AWS CloudTrail and not real production incidents. The published summary reports 801 events, including 14 synthetic anomalies. The source has been identified and its summary/schema examined; the model outcomes on it have not been inspected when this protocol is written. Earlier work already inspected the source deployment; this is not a registered trial.

Freeze all twenty existing seed-42 models from `results/journal_v4_tiesafe`; apply each unchanged to the entire committed target sample. No threshold selection, calibration, refitting or tuning on the target. The target timestamps precede the source model's historical training period, so this is a **retrospective cross-domain replay**, not forward-in-time validation. Run all models, not a selected best model. Record hashes and source attribution. The dataset has very few positive events; all metrics are descriptive for one generator, and the twenty models do not represent independent populations.

Use a fixed, lossful, label-free adapter: `timestamp` to `eventTime`; `action` verbatim to `eventName`; the action prefix before the first dot, with `generic:` prefix, to `eventSource`; `source_region` to `awsRegion`; `actor_id` to `userIdentity.principalId`; `actor_type` verbatim to `userIdentity.type`; `source_ip` to `sourceIPAddress`; `resource_id` as an opaque resource key; and `result` to an error indicator (`success` has no error, `failure` or `denied` maps to the corresponding status). These are generic cloud semantics, not recovered AWS API names, services, identity types or error codes. Unsupported CloudTrail fields, including `readOnly`, user agent, instance type and root flag, are missing and follow the existing encoder defaults. The behaviour module treats missing readOnly as false; report this limitation explicitly. Resource key strings are history-only, not numeric features.

Sort by time and event ID; fail on missing or duplicate IDs, invalid times or unsupported result/label values. A fresh historical state begins at the start of this synthetic stream. Equal timestamps are processed together. The `is_anomaly`, scenario, incident ID, source-provided rolling counts, transferred bytes, and sensitivity fields must never enter the frozen encoder or temporal history. Audit the adapter with adversarial label changes. Outcome labels are retained separately for post-score event-level confusion counts and scenario summaries; do not describe synthetic labels as confirmed attacks. No generator, external executable, AWS access or attack script is run.

Report label counts, per-configuration recall, false-positive rate, precision, F1 and event-level confusion counts using the source's synthetic labels, plus selected threshold, domain-shift caveats and the available scenario counts. Zero positive predictions do not imply perfect precision. Do not infer production false-positive rates, attack-detection accuracy on AWS, causal adaptation benefit, or Q1/Q2 readiness. Realistic independent labelled CloudTrail validation remains outstanding.
